## Field and code conventions

- Stable keys use source section and display order: `C01-S01-01` through `C01-S02-07` are the C01 keys; other rows use `CAT-S<section>-<entry>`.
- `BOM reference` is the exact JSON coordinate.
- `component/model readiness` uses compact family codes: `ok` means a current core kind or current presentation contract exists; `need` means a missing model, package contract, or physical prop. `ic/device`, `module`, `actuator`, and `prop` are intentionally not silently mapped to a scripted result.
- `diode×N:modelled` means the shared core diode contract supports standard, Schottky, and zener junction parameters; it does not imply that the row's fixture, driver, signal path, or physical prop is implemented.
- The shared core [`ic_device` contract](IC-DEVICE-MODEL.md) now satisfies the electrical IC/device model marker. The shared core [`module` contract](MODULE-MODEL.md) now satisfies the ready-made module marker; affected rows below remain blocked until their individual fixtures, source-specific behavior, physical modules, and safety/layout gaps are resolved.
- Design, safety, and buildability fields use the finding codebooks below. The detailed C01 codebook is in [`C01-READINESS-AUDIT.md`](C01-READINESS-AUDIT.md).
- `I0` and `M0` are negative evidence: no implementation or manual assembly
  has been performed for that row. `M0` is a follow-up status, not an automatic
  release blocker when automated acceptance is complete.

## Finding codebook

| Code | Meaning |

| `B-COARSE` | Source coordinates and SVG/BOM integrity checked; hole-level buildability remains unverified. |
| `I0` | No project fixture, menu/content registration, or implementation evidence. |
| `M0` | No photo, equivalent visual record, measurement, or deviation log. |
